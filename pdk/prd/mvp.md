# PRD — MVP (Product Requirements Document)

## هدف MVP
بهترین نسخه اولیه که ارزش هسته را اثبات کند — نه کامل‌ترین محصول.

## اولویت‌بندی
| قابلیت | اولویت | چرا وجود دارد | اگر حذف شود |
|--------|--------|---------------|--------------|
| ثبت‌نام + KYC ساده | P0 | ورود قانونی و اعتماد | محصول غیرقابل راه‌اندازی |
| کیف پول | P0 | موجودی و تاریخچه | هسته ندارد |
| انتقال P2P | P0 | ارزش اصلی محصول | کاربر جایگزین می‌کند |
| احراز بانکی (Passkey+2FA) | P0 | امنیت سطح بانک | ریسک بالا |
| RBAC + Audit | P0 | کنترل دسترسی | بی‌مسئولیتی |
| اعلان تراکنش/امنیتی | P0 | آگاهی لحظه‌ای | کاربر اعتماد نمی‌کند |
| پرداخت قبض | P1 | نیاز روزمره افغان | تأخیر قابل‌تحمل |
| دریافت QR/لینک | P1 | دریافت آسان | جایگزین دستی |
| پنل صراف | P2 | نرخ/خرید ارز | خارج از MVP |

| گزارش پیشرفته | P2 | تحلیل | بعداً |

## قالب PRD (برای هر قابلیت P0)
برای نمونه «انتقال P2P»:
- **هدف:** انتقال درون‌برنامه‌ای بین کاربران.
- **ارزش تجاری:** retention + فعالیت کیف پول.
- **سناریوی کاربر:** کاربر مبلغ را وارد، گیرنده را انتخاب، تأیید می‌کند.
- **قوانین کسب‌وکار:** موجودی کافی، سقف روزانه، کارمزد صفر (MVP) یا حداقل.
- **حالت‌های خطا:** موجودی ناکافی، حساب مسدود، خطای rail.
- **الزامات امنیتی:** احراز، ۲FA برای مبالغ بالا، idempotency، audit.
- **الزامات Performance:** تأیید < ۲s (p95).
- **Acceptance:** انتقال با مبلغ تصادفی در محیط تست موفق؛ تکرار idempotent.
- **ریسک:** تقلب P2P → صف بررسی.
- **وابستگی‌ها:** Wallet Ledger، Notification، RBAC.

> هر قابلیت P0 فایل جداگانه در `pdk/prd/<feature>.md` دریافت می‌کند.
