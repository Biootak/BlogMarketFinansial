# Blueprint — مدیریت کارمندان صرافی (Exchange Staff)

**نقش:** ADMIN (سیستم) / صراف OWNER  
**وظیفه اول:** «ببینم چه کسی در صرافیم کار می‌کند و دسترسی‌هایشان را مدیریت کنم.»  
**مسیر:** `/dashboard/exchanges/[id]/staff` (یا tab در صفحه جزئیات صرافی)  
**مدل DB:** `ExchangeStaff`

---

## Layout

```
┌──────────────────────────────────────────────────┐
│ کارمندان صرافی «نام صرافی»   [+ دعوت کارمند]   │
├──────────────────────────────────────────────────┤
│ [فیلتر نقش ▾]  [جستجو...]                       │
│ ┌──────────────────────────────────────────────┐ │
│ │ نام | نقش | عنوان | تاریخ ورود | وضعیت | ⋮  │ │
│ │ احمد  OWNER  مدیرعامل  ۱۴۰۳/۰۱  فعال       │ │
│ │ مریم  STAFF  تحلیلگر   ۱۴۰۳/۰۵  فعال       │ │
│ └──────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

---

## بخش‌ها

### ۱. لیست کارمندان
- جدول با ستون‌های: نام، email، نقش، عنوان شغلی، تاریخ پیوستن، وضعیت (`revokedAt` null = فعال)
- فیلتر: OWNER | MANAGER | STAFF | VIEWER | همه
- جستجو: نام یا email
- منوی ⋮ برای هر ردیف: تغییر نقش / تغییر مجوزها / لغو دسترسی

### ۲. دعوت کارمند جدید
- فرم modal: email کاربر سیستم، انتخاب نقش، عنوان شغلی (اختیاری)
- بررسی: آیا کاربر در سیستم وجود دارد؟
- invitedBy ثبت می‌شود

### ۳. مجوزهای سفارشی
- هر کارمند می‌تواند علاوه بر نقش، مجوزهای اضافه/کم داشته باشد
- `ExchangeStaff.permissions[]` = override روی پیش‌فرض نقش

### ۴. لغو دسترسی
- تأیید two-step: «آیا مطمئن هستید؟»
- `revokedAt` ثبت می‌شود (soft-delete)
- audit log ثبت می‌شود

---

## نقش‌ها و دسترسی پیش‌فرض

| نقش | می‌تواند |
|-----|----------|
| OWNER | همه عملیات صرافی + مدیریت کارمندان |
| MANAGER | تأیید quote، مدیریت معاملات، گزارش |
| STAFF | ثبت quote، مشاهده معاملات |
| VIEWER | فقط مشاهده داشبورد و گزارش |

---

## Scenarios

| سناریو | اقدام |
|--------|-------|
| کارمند جدید استخدام شد | دعوت با email → نقش STAFF → بعداً ارتقا |
| کارمند استعفا داد | لغو دسترسی → `revokedAt` ثبت + audit |
| مدیر می‌خواهد staff بتواند quote تأیید کند | مجوز سفارشی `quote:approve` اضافه کن |
| OWNER عوض شد | نقش OLD OWNER → MANAGER، کاربر جدید → OWNER |

---

## امنیت

- فقط ADMIN سیستم یا OWNER صرافی می‌توانند این صفحه را ببینند
- تغییر نقش OWNER: فقط ADMIN سیستم یا SUPERADMIN
- همه تغییرات در `AuditLog` ثبت می‌شوند
