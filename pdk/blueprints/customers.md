# Blueprint — مدیریت مشتریان صرافی (Customers)

**نقش:** ADMIN / EXCHANGE / SUPPORT  
**وظیفه اول:** «وضعیت مشتری را ببینم، سابقه معاملاتشان را بررسی کنم، KYC را مدیریت کنم.»  
**مسیر:** `/dashboard/customers`  
**مدل DB:** `Customer`, `FintechAccount`, `KycVerification`, `Transaction`

---

## بخش‌ها

### ۱. لیست مشتریان
- جدول با: نام، شماره تلفن، سطح KYC، موجودی AFN، امتیاز ریسک، وضعیت
- فیلتر: وضعیت (PROSPECT|ACTIVE|FROZEN|CLOSED)، سطح KYC، صرافی
- جستجو: نام، شماره ملی، تلفن
- صادرات CSV (ADMIN)

### ۲. جزئیات مشتری — تب خلاصه
- کارت‌های KPI: موجودی کل، تعداد معاملات، امتیاز ریسک، آخرین فعالیت
- اقدامات: فریز / فعال / مسدود کردن حساب
- یادداشت داخلی (notes)، سقف شخصی (`personalLimitAf`)

### ۳. تب KYC
- سطح فعلی، سابقه `KycVerification`‌ها
- مشاهده مدارک (docUrl, fileUrl)
- تأیید/رد KYC با یادداشت
- تاریخ انقضا (`expiresAt`)

### ۴. تب معاملات
- جدول `Transaction` مشتری با pagination
- فیلتر: نوع، وضعیت، بازه زمانی
- لینک به `FraudReview` اگر flagged شده

### ۵. تب دستگاه‌ها
- لیست `Device`‌های مشتری
- وضعیت: TRUSTED|UNVERIFIED|REVOKED
- ابطال دستگاه

## Scenarios

| سناریو | اقدام |
|--------|-------|
| مشتری اطلاعات مشکوک ثبت کرده | امتیاز ریسک را بررسی + FraudReview ایجاد |
| KYC منقضی شده | badge قرمز + ارسال اعلان به مشتری |
| درخواست ارتقا KYC | تب KYC → بررسی مدارک → تأیید با level جدید |
| حساب را باید فریز کرد | اقدامات → فریز → audit log ثبت |
| سقف معامله روزانه مشتری خاص | `personalLimitAf` ویرایش |

---

## امنیت

- EXCHANGE فقط مشتریان صرافی خودش را می‌بیند (`exchangeId` filter)
- ADMIN همه مشتریان همه صرافی‌ها
- SUPPORT فقط read — بدون ویرایش مالی
- تغییرات حساس در `AuditLog`
