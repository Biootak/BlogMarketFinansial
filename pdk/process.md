# بخش ۲ — فرآیند توسعه ۱۲ مرحله‌ای

هیچ‌گاه مستقیم کدنویسی نکن. همیشه این مراحل را طی کن:

| # | مرحله | خروجی | تایید؟ |
|---|-------|-------|--------|
| 1 | تحلیل پروژه | گزارش تحلیل (ساختار، کد، DB، API، state، کیفیت) | بله |
| 2 | تحلیل بازار | نیاز کاربر افغان، رقبای محلی، شکاف بازار | بله |
| 3 | تحلیل رقبا | مقایسه با Revolut/Wise/Nubank/Mercury + محلی | بله |
| 4 | بررسی معماری | انتخاب stack، جداسازی، ledger | بله |
| 5 | بررسی امنیت | Threat model، RBAC، رمزنگاری، احراز | بله |
| 6 | تعریف MVP | فهرست قابلیت‌های P0/P1/P2 | بله |
| 7 | نوشتن PRD | PRD هر قابلیت P0 | بله |
| 8 | طراحی دیتابیس | schema، روابط، اندیس، ledger | بله |
| 9 | طراحی API | endpointها، قراردادها، خطا، rate limit | بله |
| 10 | طراحی UI/UX | اجرای **چرخه طراحی** برای هر صفحه | بله |
| 11 | برنامه توسعه | تقسیم به taskهای قابل تست | خیر |
| 12 | پیاده‌سازی | کد + تست + بررسی (Build → Show → Improve) | خیر |

## اصول اجرا
- پس از هر مرحله تحلیلی، گزارش کامل بده و منتظر تأیید کاربر بمان.
- مرحله بعد فقط پس از تأیید مرحله قبل آغاز شود.
- برای کار بصری (مرحله ۱۰)، **چرخه طراحی** (`pdk/design-cycle.md`) الزامی است.
- Build → Show → Improve: کد بساز، کاربر بصری تست کند، بهبود بده.

## نحوه گزارش‌دهی هر مرحله
هر گزارش شامل:
1. خلاصه آنچه انجام شد.
2. تصمیم‌های کلیدی + دلیل.
3. ریسک‌ها / فرض‌ها.
4. سوال باز (در صورت وجود).
5. درخواست تأیید برای پیشبرد.
